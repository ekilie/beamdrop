# Beamdrop Project Instructions

## Documentation Maintenance Rule

**On ANY code change that affects the API surface, features, or behavior, you MUST update ALL of the following documentation:**

1. **`static/llms.txt`** — Brief LLM-discoverable API overview (also copy to `docs/llms.txt`)
2. **`static/llms-full.txt`** — Full LLM reference with schemas and SDK examples (also copy to `docs/llms-full.txt`)
3. **`docs/openapi.yaml`** — OpenAPI 3.0 specification for the S3-compatible API
4. **`docs/ai/agent-instructions.md`** — HTTP API guide for AI agents (also copy to `beamdrop-skills/skills/beamdrop/references/agent-instructions.md`)
5. **`docs/ai/SKILL.md`** — VS Code Copilot skill definition
6. **`beamdrop-skills/skills/beamdrop/SKILL.md`** — Agent Skills repository skill file
7. **`beamdrop-skills/manifest.json`** — Agent Skills manifest (update descriptions/keywords if relevant)
8. **`beamdrop-website/src/routes/docs/ai-integration.tsx`** — Website AI integration docs page
9. **`docs/beamdrop-full-docs.md`** — Complete reference documentation
10. **`README.md`** — Project README (if feature-level changes)

### What counts as an API surface change:

- New or modified endpoints (routes, handlers)
- New or changed request/response schemas
- New features (webhooks, MCP tools, auth methods)
- Changed authentication or authorization behavior
- New event types, error codes, or status codes
- New CLI flags or configuration options
- Changes to validation rules or limits

### Sync rules:

- `static/llms.txt` ↔ `docs/llms.txt` must be identical
- `static/llms-full.txt` ↔ `docs/llms-full.txt` must be identical
- `docs/ai/agent-instructions.md` ↔ `beamdrop-skills/skills/beamdrop/references/agent-instructions.md` must be identical
- The skills SKILL.md description in `beamdrop-skills/manifest.json` must match `beamdrop-skills/skills/beamdrop/SKILL.md` frontmatter

## Build Commands

```bash

go build ./...

# Frontend dashboard
cd static/frontend && pnpm run build

# Full rebuild (Go embeds frontend dist/)
cd static/frontend && pnpm run build && cd ../.. && go build ./...
```

## Architecture Notes

- **Go 1.25**, pure-Go SQLite (`glebarez/sqlite`), GORM ORM
- **Frontend**: React + TanStack Router + shadcn/ui + Tailwind CSS, embedded via `go:embed`
- **Auth**: Session auth (JWT cookies) for web UI, HMAC-SHA256 API keys for S3 API
- **MCP**: Built-in at `/mcp`, Streamable HTTP transport, JSON-RPC 2.0, same API key auth as S3
- **Webhooks**: HMAC-SHA256 signed HTTP callbacks, exponential backoff retry, event types for objects/buckets/shares/presigns
- **Storage**: Filesystem-based with atomic writes, per-object locking, bucket isolation
- **Webhook routes**: `/api/v1/webhooks` (S3 API auth) + `/webhooks` (session auth for dashboard)
